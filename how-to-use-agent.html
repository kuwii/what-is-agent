怎么用 Agent？

读完正文你可能好奇：道理都懂了，可真打开一个 Agent 软件，到底该怎么用？

1 Agent 软件 ≠ LLM 本身

很多人第一次听说 Agent 的反应是："这不就是 ChatGPT 吗？"——接近了，但不完全对。

回忆一下正文：LLM 是一台部署在厂商机房里的接龙机，你只能通过 API 跟它打交道——发一段文字过去，它回一段文字回来。仅此而已。它读不了你电脑上的文件，跑不了命令，更不记得你五分钟前让它干了什么。

那真正在你电脑上干活的"人"是谁？是 Agent 软件。它是一个装在你自己机器上的程序，负责三件事：跟你对话、替你调用 LLM 的 API、以及最关键的——跑正文里那个Agent 循环：LLM 说暗号 → 执行工具 → 把结果喂回去 → 循环，直到活干完。

LLM 只提供"脑子"（API），Agent 软件提供手脚，还在你本地跑循环

一句话总结：LLM 是大脑，API 是接通大脑的电话线，Agent 软件是那个有手有脚、真正干活的雇工。

"那 Agent 软件厂商和 LLM 厂商不是一回事？"对。绝大多数 Agent 软件自己不做模型，只是让你选一个模型接进去——有的甚至允许你干活干到一半换模型。模型是可替换的大脑，Agent 才是不变的身体。

2 Agent 软件长什么样

脑子都一样，身体却有好几种。市面上最常见的形态有三种：

  • 终端型：一个黑底白字的命令行窗口，敲一句话就开始聊。看着最"黑客"，其实最简单——就是一个能跑命令的聊天框。
  • 编辑器插件型：装在代码编辑器里，侧边开一个聊天窗口，选中的代码可以直接丢给它。
  • 独立应用型：一个独立的桌面程序或网页，有的还能直接操控浏览器和桌面。

不管哪种形态，内核都是同一套：一个对话框 + 一组工具 + 一个 Agent 循环。学会一个，换个产品不过是熟悉一下按钮位置的事。

本文以最常见、工具最标准的编码类 Agent 为例。其他类型的 Agent（比如能替你操作浏览器的）原理相同，只是工具箱不一样。

3 出厂标配的三件工具

正文说过，Agent = LLM + 工具 + 循环。那编码类 Agent 出厂自带的工具箱里有什么？通常就三件：

  • 对话：你在对话框里下达任务，它回复你。这是你和它打交道的唯一入口。
  • 读写文件：它能看你项目里的文件、新建文件、修改文件。"帮我把这份文档的标题改一下"——它是真的会去改，不是告诉你怎么改。
  • 执行命令：它能在你的终端里跑命令——安装依赖、运行测试、查版本历史，等等。

这三件看着简单，放进循环里就很能打了：读文件发现问题 → 改掉 → 跑测试 → 没通过 → 读报错再改 → 通过 → 向你汇报。正文里那个抽象的"Agent 循环"，落到编码 Agent 身上就是这么转起来的。

只有这三件吗？当然不止，搜索、浏览网页等也常见，不同产品自带的工具不一样。但"对话 + 文件 + 命令"是最常见的标配——有了这三样，大部分编程任务就能转起来。

4 动手之前，它先问你

接下来是新手最容易不适应的地方：这玩意跑在你的电脑上，能改你的文件、能执行命令——它该不会乱来吧？

还真不会。Agent 软件有一条刻在骨子里的规矩：危险动作要先经过你点头。它准备改文件、跑命令之前，通常会先停下来问你一句："我想干这个，行吗？"你点同意它才动手，拒绝就原地打住。

危险动作一律先暂停、先请示——这是你的安全阀

第一次用 Agent，你会看到它不停地弹确认。别嫌烦，这是你的安全阀。给新手两条建议：

  • 别条件反射地一路点"同意"。尤其是你看不懂的命令——先问它一句"这条命令是干什么的"，再决定放不放行。
  • 松紧可以自己调。大多数产品允许你设置确认的严格程度，从"事事请示"到"全自动"都有。建议先严后松，用熟了再放开。

为什么非要问我？它自己决定不行吗？因为 LLM 的输出是有随机性的——正文说过，它会一本正经地胡说八道。给危险动作加一道人工关卡，是最便宜的保险。

5 扩展工具：MCP

标配工具箱总归有限。想让 Agent 查你们团队的内部文档？看天气？操作某个特定的软件？

答案是 MCP（模型上下文协议）。正文一句话带过它：工具对接的标准接口。展开说就是——LLM 只会"说暗号"，工具们各说各的方言，MCP 就是行业统一的工具对接标准：任何工具只要按这个标准包装成一个 MCP 服务器（一个独立的小程序），任何支持 MCP 的 Agent 就都能直接用上它。

工具按标准包装成"服务器"，Agent 即插即用

怎么用？两步：

  • ① 找（或写）一个 MCP 服务器。开源社区里多如牛毛：搜索、数据库、笔记软件、日历……你能想到的几乎都有人做好了。
  • ② 在 Agent 的设置里登记它。告诉 Agent"这里有个工具，这样启动它"。登记完，这个工具就出现在 LLM 的暗号菜单里了。

整个过程不需要你写一行 AI 代码——就是给 Agent 装插件。

6 开工前的规矩：指令文件

工具有了，还有个问题：Agent 对你和你的项目一无所知。每次开工，难道都要重复一遍"用中文回答我""我们项目用这种格式"？

不用。几乎所有 Agent 软件都支持指令文件：一个普通的文本文件，你提前把规矩写进去，Agent 每次开工前会自动读一遍。就像给新来的员工贴了一张入职须知。

这张须知通常分两级：

  • 项目级：放在项目文件夹里，只对这个项目生效。比如"这个项目的注释一律用中文写""别碰那个目录"。
  • 用户级：放在你电脑上的固定位置，对你所有的项目生效。比如"永远用中文回答我""动手之前先解释方案"。

具体叫什么文件名、放在哪个目录，各家产品不一样，但思路完全一致：永远不变的规矩写进文件，别每次费口舌。

7 按需加载的说明书：Skill

指令文件解决了"永久的规矩"，但还有一类知识：只在特定任务里才用得上。比如"怎么做一份 PPT""怎么处理表格"——这些全塞进指令文件，Agent 每次开工都得读一本厚手册，还大半用不上。

于是有了 Skill（技能）：一份按需加载的说明书。每份 Skill 是一个小文档，开头写着一小段自我介绍——我叫什么、擅长干什么——正文才是详细步骤。Agent 启动时只读所有 Skill 的自我介绍（一份很薄的目录），遇到对得上的任务，才翻开对应说明书的全文。

那段自我介绍长什么样？写在文档最顶部，用两行 --- 包起来，业内叫 frontmatter：

---
name: make-ppt
description: 根据大纲生成演示 PPT
---

（这里开始是正文：详细步骤……）

Skill 有两种用法：Agent 看目录自动选用；或者你在对话框里敲一个 / 再加 Skill 的名字，手动点名——就像自己从抽屉里抽出一份档案。少数 Skill 被标记为"仅供内部参考"，不会出现在 / 菜单里，只有 Agent 自己能翻。

跟指令文件一样，Skill 也分项目级和用户级：放在项目文件夹里的只服务这个项目，放在用户目录里的服务你所有项目。

工具 vs Skill，区别在哪？工具管"能操作什么"，Skill 管"怎么做好"。一个扩展手脚，一个扩展经验。

8 给新手的几条实操建议

机制讲完了。最后补几句实操层面的大实话，都是踩过坑才知道的：

像给人派活一样说话

别说"帮我修一下"。要说"这个文件运行时报错了，报错信息是这个，请排查原因"。任务越具体、给的背景越多，Agent 干活越靠谱。含糊派活，必然得到含糊的结果。

别信"搞定了"，要验收

Agent 说"完成了"，只代表它走完了自己的流程，不代表结果是对的——LLM 会一本正经地胡说八道，Agent 也会。改了代码就跑一下看看，写了文档就读一遍。你才是最终验收人。

新任务，新对话

正文说过：LLM 没有记忆，所谓记忆就是每次把聊天记录全发一遍。聊得越长，花钱越多，Agent 还越容易"走神"。养成习惯：一个任务干完，下个任务开个新对话。

心里有本账

Agent 干活是循环，一个复杂任务可能调几十次 LLM 的 API，token 消耗远超普通聊天。如果你按 API 用量付费，一个任务花掉一杯奶茶钱很正常。接大活之前，先看看账单怎么算。

Agent 软件听着新鲜，拆开看不过如此：一个对话框、一组工具、一个循环，外加几样安全和配置机制。下次再有人在你面前秀 Agent，你可以淡定一句："不就是聊天框 + 工具 + 规矩嘛，我用过。"

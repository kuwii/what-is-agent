机器学习，神经网络与大语言模型（LLM）

读完正文你可能好奇：这台"接龙机"到底是怎么"学"出来的？这篇从最底层的概念讲起。

1 机器学习：不写规则，给例子

AI 这个词听着玄，但它最底层的想法朴素得惊人：不告诉机器规则，给它看例子，让它自己总结规律。这个思路，就叫机器学习（Machine Learning）。

拿垃圾邮件过滤举例。传统思路是人写规则："含'中奖'→ 垃圾邮件"。但骗子会进化，规则永远追不上骗术。机器学习的思路反过来：找来 10 万封已经标记好"垃圾/正常"的邮件，让机器自己去琢磨——它可能发现"中奖 + 链接 + 三个感叹号"的组合很可疑。规则不是人写的，是从例子里"悟"出来的。

怎么做到的？机器内部有一大堆可以拧的"旋钮"（学名参数）。训练就是不停地试：猜错了，就把旋钮往回调一点点，直到猜得足够准。就像学生刷题——不是背答案，而是做完一万道题之后，总结出了解题套路。

先用带答案的例子训练，训练完就能对新情况做判断

"AI 会学习"翻译成人话：一台有百万个旋钮的机器，靠海量例子把旋钮转到合适的位置。旋钮越多、例子越多，悟出来的规律就越细——仅此而已。

2 任务说穿了就俩：预测和分类

机器学习的任务千变万化——推荐商品、识别人脸、翻译文章……但扒掉外衣，基本就两类：

  • 预测：猜一个数。明天多少度？这套房子值多少钱？
  • 分类：分一个类。这封邮件是垃圾吗？这张照片是猫是狗？

左：根据已有数据猜一个数值；右：把东西分成几堆

两者的界限其实很模糊——分类本质上是在预测"属于每个类别的可能性"，比如"这张图 92% 是猫"。

还记得正文说 LLM 是台接龙机吗？"猜下一个词"其实就是一道超大型分类题：词表里几万个候选 token，算出哪个最可能接上。所以 LLM 再风光，干的也是机器学习最古老的活儿。

3 神经网络：一台层层加工的机器

早期机器学习有个软肋：人得先告诉机器"看哪里"。比如识别猫，人得先定义好"尖耳朵、胡须、圆脸"这些特征，机器只管最后一步判断。简单任务还行，复杂任务人就定义不过来了——你试试给"猫"写一份完整定义？

转折的思路很直接：干脆让机器连"看哪里"也自己学。于是有了神经网络——一台受大脑启发的"加工流水线"：数据从一层层"神经元"中间穿过，每一层做一点点简单加工，层层提炼，自己从原始像素里总结出"边缘 → 形状 → 物体"。层数足够多的神经网络，就叫深度学习。

打个比方：就像工厂流水线——原料进去，每个工位拧一颗螺丝，出来就是成品。单个工位简单到可笑，但几百个工位串起来，就能干人定义不了的活。

数据从左进、从右出，每经过一层就被加工一次——每一层都在提炼更抽象的特征

为什么这几年才火？

神经网络的想法上世纪就有了，但一直不温不火。直到 2012 年前后，三样东西第一次凑齐了：

  • 数据：互联网攒了几十年的文字、图片、视频，全成了教材；
  • 算力：GPU 被拉来干 AI，几千块显卡一起上阵（👉 番外篇《LLM 为什么用显卡》讲的就是这段）；
  • 算法：研究者改进了训练技巧，让几百层的网络真的能训起来。

粮食、力气、方法同时到位，深度学习这才起飞。不是突然变聪明，是条件终于凑齐了。

4 语言也能"算"？从 NLP 到 LLM

文字看起来和数字八竿子打不着，怎么让机器"算"语言？关键一步：把词变成数字（词向量）。意思相近的词，变出来的数字也相近——"猫"和"狗"挨得近，和"发票"离得远。文字一旦变成数字，神经网络就能算了。处理语言的这门手艺，就叫自然语言处理（NLP）。

2017 年，关键发明登场：Transformer 架构。它有个"注意力"机制——读一个词时，能同时看到整句话的所有词，前后对照。之前的模型像金鱼，读到句尾就忘了句首；Transformer 能一目十行。

再往后，故事简单粗暴：更大的网络 + 更多的数据 + 更多的算力 = 更强的能力。GPT 系列一路堆上去，堆到 2022 年底 ChatGPT 出圈——大家突然发现：这台只会"猜下一个词"的机器，聊起天来居然像个人。

NLP 的进化链：每一代都在回答同一个问题——怎么让机器更懂人话

堆规模就能变强？这个规律业内叫 Scaling Law，俗称"大力出奇迹"：同一个简单的任务，规模大到一定程度，能力会突然上台阶。没人完全搞懂为什么，但它确实管用。

5 LLM 出厂记：训练三部曲

正文说过 LLM 是接龙机。但这台接龙机出厂前，得经过三道工序：

先博览群书，再学做人，最后上岗接龙

  • ① 预训练：博览群书。把互联网上能搞到的文字——书籍、网页、百科、代码——全喂给它，只练一件事：猜下一个词。几万亿个词刷下来，它为了猜得准，被迫学会了语法、常识、逻辑。毕竟要猜对"水往低处__"，你多少得懂点物理。
  • ② 对齐微调：学做人。刚练成的模型是个"野生学霸"，会接龙但不一定会聊天。于是用人工挑选的"好回答"继续调教，再让人类给它的回答打分，教它什么话有用、什么话不能说。这一步叫对齐。
  • ③ 推理：上岗干活。你用的时候，它不再学习，只是不停地接龙——就是正文里那个循环。

它在偷偷学我吗？没有。你聊天时它的参数早就冻结了，只是在用训练时学到的本事现场接龙。它"记得"你说的话，靠的是正文里那招——每次把聊天记录全发一遍。

6 稠密 vs MoE：全员上岗 vs 专科门诊

前面说过"大力出奇迹"，于是参数越堆越多——从几亿到几百亿、几千亿。这么多参数怎么组织？最直白的答案是：全部捏在一起，每回答一个问题，所有参数齐刷刷上阵。这种结构叫稠密模型（Dense）。就像一家公司，每来一单，从 CEO 到实习生全员打卡——扎实，但人力成本拉满。

成本是实打实的：参数越多，训练要越多显卡，回答问题越慢，电费也越吓人。既想要大模型的脑子，又付不起大模型的账单，怎么办？有人出了个主意：MoE（Mixture of Experts，混合专家）。

MoE 把模型拆成许多个叫"专家"的小网络，再配一个路由器（传达室大爷）站在前面。问题来了，路由器看一眼，把它分给最擅长这类问题的两三个专家，其余专家继续休息。就像去大医院看病：你不需要挂全医院所有医生的号，分诊台把你分给对口的两三个专科大夫。

左：稠密模型，所有参数每次都干活；右：MoE，路由器分诊，被点名的专家才上岗

所以 MoE 模型要用两个数字描述：总参数量（医院有多少医生）和激活参数量（这次真正给你看病的有几个）。听到"总参数几千亿、激活几百亿"别被吓到——意思是模型确实很大，但每个问题只动用其中一小部分。大模型的脑子，小模型的账单，这就是全部把戏。

MoE 省显存吗？不省。休息的专家也得"坐在诊室里"——所有参数依然要装进显存。MoE 省的是算力，不是存储：用更大的显存占用和更复杂的训练，换来更便宜、更快的回答。

7 多模态：给 LLM 配上眼睛和耳朵

LLM 只认 token——一串数字。那它怎么看图、听声音？答案很直白：请翻译官。

图片：切成一个个小方块，每块经一个"视觉编码器"翻译成数字。声音：同理，把音频切成小段，翻译成数字序列。翻译完之后，在 LLM 眼里，这些数字和文字 token 没本质区别——都是"可以一起接龙的素材"。

不管图片、声音还是文字，统统翻译成数字，再交给 LLM 处理

反过来也行：LLM 输出特定的数字，再让另一个模型翻译回图片、声音——AI 画画、AI 配音就是这么来的。

打个比方：就像联合国开会，各国代表说自己的语言，同传统一翻译成工作语言。LLM 只需要懂一种"数字语"，剩下的交给翻译官。所以"多模态大模型"听着唬人，拆开就是：LLM + 一群翻译官。

∞ 总结

回顾一下这条进化链，每一环都朴素得很：

从例子里找规律 → 层层加工的神经网络 → 堆到超大规模

机器学习 + 深度学习 + 大力出奇迹 = LLM

而 LLM 从头到尾干的活，还是机器学习最朴素的那件事——猜下一个。

下次有人把 AI 吹得神乎其神，你可以淡定一笑："不就是台会刷题的接龙机嘛。"
